# 出队财务工具

这是北航凌峰社团出队自用的处理程序，用于根据成员职能意向自动生成职能分配建议，并生成出队财务报表，减少领队的重复性工作。职能分配和职能负责人根据问卷自动生成。

## 目录结构

```text
.
├── src/                     # Python 源码
│   ├── app.py               # 可视化界面
│   ├── finance.py           # 报名导入与 Excel 导出
│   ├── duties.py            # 职能分配逻辑
│   └── launcher.py          # exe 启动入口
├── scripts/
│   └── build_windows.bat    # Windows 打包脚本
├── data/samples/            # demo_signup.xlsx 为可公开的虚构测试样例
├── requirements.txt         # 运行依赖
├── requirements-build.txt   # 打包依赖
└── README.md
```

运行和打包命令均从项目根目录执行；打包输出位于 `dist/`，由 Git 忽略。

## 本地运行

使用 Python 3.10 或更新版本：

```bash
python -m pip install -r requirements.txt
python -m streamlit run src/app.py
```

在浏览器中打开终端显示的本地地址。上传含“姓名”“报名时间”列的 xlsx 明细，；按报名时间选择成员、指定领队/副领队，填写包车费和对讲机数量后下载报表。

仓库提供 `data/samples/demo_signup.xlsx`：按原问卷 29 列结构全新随机生成的 15 人虚构报名明细，可直接通过界面导入，选择领队、副领队和财务后测试分配及报表导出。姓名、入学年份、时间、志愿、装备和所有联系信息均为合成内容，未复制原报名记录。电话使用 000 前缀、证件号使用 000000 无效地区码，不能用于实际联系或投保。其他本地 Excel 继续由 Git 忽略。问卷统计汇总不含个人记录，不能作为成员明细导入。重复姓名保留为不同报名记录。

默认每人预收 100 元，普通队员领队费 10 元，领队和副领队免收；保险全员 2 元；登山杖每人 12 元，头灯每人 8 元。包车费和对讲机数量×单价由所有人均摊。对讲机固定每台 12 元。

导出文件包含“费用参数”“财务报表”和“职能安排”。各费用和余额均使用 Excel 公式，余额允许负数；用 Excel/WPS 打开后计算公式（openpyxl 本身不计算公式）。分摊不提前舍入，余额四舍五入至分，可能存在分币尾差。正余额退款，负余额补缴。原始文件不会修改。

## Windows exe 分发

打包人员在 Windows 10/11 64 位电脑上安装 Python 3.11（含 Python Launcher），将项目放在本地目录，双击 `scripts/build_windows.bat`。首次构建需要联网安装依赖。成功后得到：

```
dist/LingfengFinance.exe
```

将这个 exe 发给其他人即可，使用者不需要安装 Python，也不需要项目源码。双击 exe 后会先弹出最新版本获取提示，地址为 https://github.com/maojianhuan/lingfeng_hiking 。点击“确定”后启动本机服务，并通过默认浏览器使用界面。首次启动需要解包，可能稍慢；无需上传文件到外部服务器。输入文件通过界面选择，报表通过浏览器下载。

运行时保留控制台窗口；用完关闭控制台（或按 Ctrl+C）即可退出程序，单独关闭浏览器标签页不会退出。服务只监听本机 127.0.0.1:8501；该端口若被占用，请先关闭之前启动的程序再打开。不要同时运行多个实例。

此处提供的是打包配置，当前 Linux 开发环境尚未生成或实测 Windows exe。发布前应在一台未安装 Python 的 Windows 电脑上检查：双击启动、手动输入/导入名单、选择成员、下载 Excel，以及用 Excel/WPS 打开验证余额公式。

## Git 版本管理

默认开发分支为 `main`。源码、依赖清单及打包脚本纳入版本管理；虚拟环境、缓存、构建产物和本地 Excel 数据（公开虚构样例 `demo_signup.xlsx` 除外）由 `.gitignore` 排除，原文件仍保留在磁盘上。

检查并提交一次迭代：

```bash
git status
git diff
git add .
git diff --cached
git commit -m "描述本次改动"
```

确认 Windows 构建和使用测试通过后，可为对应提交添加版本标签，例如 `git tag -a v0.1.0 -m "首个发布版本"`。将生成的 exe 作为发布附件分发，不将其加入源码仓库。当前尚未配置远程仓库。


## 角色与职能安排

成员角色可标记为队员、领队或副领队，页面显示领队及副领队名单，财务表按角色免除领队费。

报名明细可额外包含“职能意向”和“是否愿意担任职能负责”列。意向支持后勤、队医、装备、摄影、财务、队记，按优先顺序以顿号或逗号分隔，例如“摄影、队记、后勤”；是否愿意负责填“是”或“否”。志愿和负责意愿直接从问卷读取，无需逐人填写。

财务与领队、副领队一样在界面单选指定，三者不可兼任，不参与其他职能自动分配。财务仍收取 10 元领队费。其他职能人数上限为剩余普通队员人数÷5 向上取整，包含负责人。职能分配优先入学年份较早者，同年份按报名顺序满足志愿；未满足志愿者按同样顺序随机补入剩余名额。负责人优先从愿意负责者中选择入学最早者，同年随机；无人愿意时从该职能所有成员中选择入学最早者，同年随机指定。问卷须包含“入学年份”或原始“年级”字段。当前会话中名单和角色不变时保留随机结果，修改费用或下载不会重抽；重新上传不同问卷或修改名单、角色时重新分配。界面可展开查看结果，不再逐人填写或配置名额。领队和副领队不参加其他职能分配。界面和 Excel“职能安排”表第一行依次列出领队、副领队、财务，后续每项职能一行列出成员，负责人排在第一位并标注“（职能负责）”，不再设置角色列。

支持问卷星“按文本”明细的原始列名：提交答卷时间、你的姓名、职能志愿、是否愿意担任职能负责、需要租借的装备。自动识别题号前缀、箭头分隔的职能排名以及装备借用信息。支持其 YYYY/MM/DD H:MM:SS 时间格式。

上传的 15 人明细已原地脱敏：姓名、学号、电话、微信、身份证、紧急联系人、IP、来源详情及备注替换为虚构内容。电话使用 000 前缀，身份证使用无效地区码 000000，避免误当真实联系方式或有效证件。此数据仅用于功能演示，保留报名顺序、志愿及装备选择，不应视为严格匿名化数据用于公开发布。


## 在 Linux 上通过 GitHub 构建 Windows exe

已提供 `.github/workflows/build-windows.yml`，在 GitHub 的 Windows 机器上执行相同的打包脚本，不需要本机安装 Windows。构建支持手动触发及推送 `v*` 版本标签触发，普通代码推送不会触发。

1. 登录 GitHub，新建空仓库（例如 `lingfeng-outing`），不要勾选自动生成 README、许可证或 .gitignore。
2. 在本机项目根目录执行以下命令，将 `你的用户名` 替换为实际 GitHub 用户名。首次提交前检查暂存列表；Excel 和构建产物默认不提交。

```bash
git add .
git diff --cached --stat
git commit -m "初始化出队职能与财务工具"
git remote add origin https://github.com/你的用户名/lingfeng-outing.git
git push -u origin main
```

若 Git 提示缺少作者信息，先在本仓库执行 `git config user.name "你的名字"` 和 `git config user.email "你的邮箱"`，再提交。HTTPS 推送需要使用 GitHub 支持的凭据认证（如个人访问令牌），不能使用账号密码；也可以使用已配置的 SSH 地址。

3. 打开 GitHub 仓库的 **Actions → Build Windows EXE → Run workflow**，选择 `main` 后运行。若仓库提示 Actions 未启用，先按页面提示启用。
4. 构建成功后进入该次运行页面，在底部 **Artifacts** 中下载 `LingfengFinance-Windows-x64`，解压得到 `LingfengFinance.exe`。构建产物保留 30 天；失败时查看对应步骤日志。
5. 在 Windows 上验证启动、导入及下载报表后，将 exe 发给使用者。

后续迭代提交并推送代码后，可再次手动构建，或推送版本标签自动构建：

```bash
git tag -a v0.1.0 -m "首个发布版本"
git push origin v0.1.0
```

手动 Run workflow 只生成 Actions 构建产物；推送 `v*` 标签会在构建成功后自动创建对应的 GitHub Release 并直接附上 `LingfengFinance.exe`，无需下载 ZIP 后再手动上传。使用内置 `GITHUB_TOKEN` 的 `contents: write` 权限，无需另配令牌。同一版本标签只发布一次，后续更新使用新标签。自动构建成功不代表 Windows 上的所有交互都已验证。源码仓库包含虚构样例 `data/samples/demo_signup.xlsx`，用户可下载后在界面上传，或选择自己的真实明细文件。


## 购买保险信息导出

选择本次出队成员后，可单独下载“出队保险名单.xlsx”，仅包含姓名、身份证号、手机号三列，按报名时间排序，与职能和财务分配无关。支持导入标准“身份证号”“手机号”列，或问卷中的“身份证号（仅用于购买保险）”“联系方式（电话）”字段。

保险信息直接读取问卷；缺失时提示更正原始明细并重新上传，不在界面逐人填写。身份证号与手机号均以文本导出，保留前导零及身份证末尾 X。源表身份证号须保存为文本；已存成数值的证件号码可能丢失精度，程序要求从原始记录重新填写。脱敏样例仅供演示，不能用于实际投保。

日常操作仅需上传问卷、选择出队成员，再补充领队、副领队、财务、包车费及对讲机数量。装备借用、保险信息、职能意向与负责意愿均由问卷读取。

领队、副领队均为单选；更换领队不会清空副领队，同一人不能兼任两者。

包车费输入整数元，默认 1000 元；对讲机数量默认 2 台。

财务报表直接展示登山杖费、头灯费，不再包含是否借用的独立列；费用仍按问卷借用记录自动计算。


发布下一版本（例如 v0.2.0）：先提交并推送修改，再推送新标签。

```bash
git add .
git commit -m "描述本次更新"
git push origin main
git tag -a v0.2.0 -m "发布 v0.2.0"
git push origin v0.2.0
```

等待 Actions 成功后，用户可直接在 https://github.com/maojianhuan/lingfeng_hiking/releases/latest 下载 exe。无需手动解压或搬运构建附件；程序不会自动更新用户电脑上的旧 exe，用户仍需下载新版本。
